# Стройконтроль СМР — аналитический проект к РК-1

Самостоятельный курсовой проект по теме «Автоматизация строительного контроля и управления качеством СМР». Связь с дипломом не заявляется. Работа охватывает **аналитику**, а разработка ERP-приложения и внедрение остаются за её пределами.

Источник: [Chicago Building Violations](https://data.cityofchicago.org/Buildings/Building-Violations/22u3-xenr), набор `22u3-xenr`. Это журнал нарушений, а не полный реестр всех проверок. Модель оценивает FAILED среди зарегистрированных инспекций с однозначным FAILED/PASSED. Применимость к локальным СМР ещё не подтверждена.

## Быстрое воспроизведение без скачивания

Проверено на Python 3.14.5; точные версии прямых зависимостей сохранены в `requirements.txt`, полный список окружения — в `requirements-lock.txt`. На других версиях Python нужна доступность совместимых колёс этих версий.

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python -m src.pipeline --from-snapshot
python -m src.artifacts
```

В Git включены компактные `data/processed/inspections.parquet` и `model_data.parquet` именно того снимка, на котором построен отчёт. Поэтому EDA и baseline воспроизводятся без интернета. Качество raw-слоя при этом читается из сохранённого аудита; для его независимого пересчёта нужен полный запуск ниже.

Notebook использует те же функции из `src/`, чтобы результаты интерактивного и командного запуска совпадали. Выберите ядро созданного окружения. При необходимости зарегистрируйте его:

```bash
python -m ipykernel install --user --name stroykontrol-smr --display-name 'Стройконтроль СМР'
```

Географическая подложка включает 77 районов Чикаго и озеро Мичиган. Файлы GeoJSON и происхождение с SHA-256 сохранены в `data/geography/`; построение карты не требует интернета или ключа API. Источники: [City of Chicago](https://data.cityofchicago.org/Facilities-Geographic-Boundaries/Boundaries-Community-Areas/igwz-8jzy), [Natural Earth](https://www.naturalearthdata.com/about/terms-of-use/). Только карту можно пересобрать командой `python -m src.geography`.

## Полное воспроизведение: скачивание и аудит

```bash
python -m src.pipeline
python -m src.artifacts
```

Скачивается полный CSV из первоисточника, около 0.93 ГБ; Parquet сохраняется локально. Нужны интернет, несколько ГБ диска и достаточная память для анализа. CSV читается строго, ошибочные строки не пропускаются. Новый живой экспорт может отличаться от сдаваемого снимка; его дата и SHA-256 записываются в `data/raw/manifest.json`. Внутри одного локального снимка изменение CSV обнаруживается проверкой хеша. Чтобы получить другой снимок, сохраните старый локальный raw-каталог и используйте пустой `data/raw/`. Граница периода исследования закреплена в `CUTOFF='2026-10-09'`; более поздние события не войдут в таблицу инспекций без явного изменения протокола.

При недоступности экспорта скачайте CSV через портал и сохраните как `data/raw/building_violations.csv`. Авторизация для использованного открытого экспорта не требовалась; серверные ограничения и изменения доступности возможны.

После пересчёта `python -m src.artifacts` создаёт DOCX, Markdown и PPTX. Для экспорта актуальных PDF нужен LibreOffice:

```bash
soffice --headless --convert-to pdf --outdir reports reports/course_report.docx
python -m src.export_pdf
```

Поставляемые PDF экспортированы и проверены. При пересборке отчёта переносы страниц могут зависеть от установленных шрифтов. В PPTX сохранены Bahnschrift, Arial и Consolas исходного автора. Для совпадения шрифтов при открытии PPTX они должны быть установлены. На этой macOS Bahnschrift отсутствует: при PDF-экспорте используется установленный DIN Alternate той же группы дизайна; Arial и Consolas загружаются из локальных шрифтов Microsoft Office. Это явная замена только для PDF; исходные имена в PPTX не меняются.

## Протокол модели

- Единица наблюдения: `inspection_number`, а не строка нарушения.
- Метка: FAILED=1, PASSED=0; CLOSED/HOLD/UNKNOWN и конфликтные инспекции исключаются.
- Train: 2006–2023, validation: 2024, test: 2025; 2026 неполный и не используется в оценке.
- Dummy prior и логистическая регрессия; one-hot и числовая импутация обучаются только на train.
- Входы: служба, категория, год, sin/cos месяца, день недели, координаты. Текущие нарушения, результат, устранение, waived и история меток не входят в модель.
- Порог выбирается на validation по минимуму `5*FN+FP`; цены условные. AP, ROC-AUC, precision, recall, F1, balanced accuracy, Brier и матрицы ошибок сохранены.
- Критерий: AP ≥ Dummy AP + 0.05, recall ≥ 0.80, precision ≥ доли FAILED на тесте. Выполнение критерия фиксируется в `baseline.json`, практическая пригодность требует локальной проверки.

## Ограничения и происхождение

Восьмипунктовый чек-лист составлен как стандартный аналитический: подробный перечень преподавателя не был предоставлен. Данные одного города и журнала нарушений имеют смещение отбора. Современный снимок не содержит версии каждого поля на момент осмотра; временной тест уменьшает смешение периодов, но полностью этот риск не устраняет. Различия служб и территорий описательные, без причинных выводов.

Исходная презентация, notebooks, статистика и результаты замеров от 26.09.2026 сохранены в `archive/`. Старые 2 030 101 строки, 15 признаков и частоты по всем статусам относятся к прежнему протоколу. Их нельзя смешивать с новой бинарной выборкой и новыми метриками. Старые скорости чтения не измерялись повторно и помечены историческими в приложении презентации.

На исходные муниципальные данные новая лицензия не назначается. Компактные таблицы сохраняют только поля, необходимые для анализа; адреса и свободный текст комментариев из них удалены. Описание и ограничения первоисточника см. в метаданных и отчёте.
